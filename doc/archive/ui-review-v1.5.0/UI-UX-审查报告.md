## 0. 一页结论

LightTier 的视觉体系已经相当完整：奶油主题、卡片节奏、弹窗动效、主题预览和双语体系都有明显打磨痕迹，整体观感整洁、克制、有一致性。

但这套界面**看起来比它实际用起来更完整**。本轮发现 3 个可能导致配置或设置数据丢失的 P0 问题；键盘和读屏用户无法完成主题切换、编辑开关、服务安装方式选择等核心操作；移动端设置页因多根节点与样式覆盖问题退化成遮罩弹窗，且只能看到第一个分类；默认 1000×650 窗口下配置详情头部明显拥挤；全局隐藏滚动条与固定 FAB 又掩盖了长内容的可达性。

## 1. 审查范围与方法

### 1.1 范围

- 布局壳：`src/layout/NewLayout.vue`、`src/components/FloatingMenu`、`src/App.vue`
- 页面：全局总览、运行监控、配置（列表 / 详情 / 编辑 / 新增）、Web 配置、设置、主题、引导
- 通用组件：`CreamDialog`、`SettingsDialog`、`ThemeDialog`、`OnboardingGuide`、`TrendChart`、`CodeEditor`

- 国际化：`src/locales/zh-CN.ts`、`src/locales/en.ts`

### 1.2 方法

1. 以 `pnpm dev` 浏览器 Mock 模式运行应用，逐页操作并记录实际反馈。
2. 通过固定尺寸 iframe 模拟 **1000×650（Tauri 默认窗口）** 与 **390×844（手机）** 视口，规避浏览器 `resizeTo` 无效的问题。
3. 共保存 18 张截图，覆盖桌面、默认窗口、手机、英文界面、设置、主题、编辑弹窗与 Web 配置。
4. 对关键控件做 DOM 抽查：角色、`tabIndex`、可聚焦数量、`aria-*`、`label` 关联、实际计算样式。
5. 对照 `theme.css` 颜色 token 计算 WCAG 对比度。
6. 对交互实现做静态代码审查，定位具体文件与行号。

### 1.3 环境与限制

- **未运行真实 Tauri 桌面窗口**：截图与交互均来自浏览器 Mock；窗口拖拽、托盘、真实文件 I/O、内核调用未在本轮实机验证。1000×650 为 iframe 模拟。
- **未运行 Android 真机 / 模拟器**：`isAndroid()` 依赖 Tauri OS 插件，浏览器恒为 `false`；Android 结论主要来自代码与二级路由模拟，移动端设置页截图是在非 Android 环境通过 `#/new/settings` 触发，恰好暴露了 `inline` 失效问题。
- **锁屏界面未完成视觉实测**：浏览器 Mock 下 `App` 初始化阶段因托盘 API 抛错中断（见 UX-207），锁屏流程无法按预期触发；仅完成设置密码的写入/清除验证与代码审查。
- 截图中底部的语言/地球小胶囊属于**开发预览工具浮层**，黄色边框属于 **iframe 测试边框**，均非 LightTier 产品 UI。
- 未运行自动化 axe 扫描或真实读屏软件；可访问性结论基于 DOM 抽查、代码审查和人工启发式检查。
- Mock 数据固定为 5 个配置、1 个运行实例；生产环境的数据规模、异常文件与内核版本差异需另外验证。

## 2. 设计体系与值得保留的部分

1. **主题 token 覆盖完整**：背景、文字、状态色、间距、圆角、阴影、动效曲线都有变量，且间距以 4px 为基准，视觉节奏统一。
2. **CreamDialog 的基础工程较好**：`role="dialog"`、`aria-modal`、Esc 关闭、Tab 焦点圈定、关闭后焦点还原，均已实现（`src/components/CreamDialog/index.vue:22-24, 146-166`）。
3. **主题预览使用 Shadow DOM 隔离**：内置主题与外置主题的变量注入不会互相污染，是一个有前瞻性的实现。
4. **双语体系完整**：用户可见文案基本都走 i18n，中英文页面结构一致；英文长文案也没有出现明显截断。
5. **平台差异有意识**：Android 隐藏托盘、服务管理、内核下载等桌面专属内容，避免把桌面交互硬塞进手机。
6. **触控与动效降级有处理**：`adaptive.css` 对 `hover: none` 提升触控目标，对 `prefers-reduced-motion` 做了动效弱化。
7. **状态语义基本成形**：运行中/已停止用绿色/灰色圆点区分，危险操作用粉色描边，信息层级清楚。
8. **空态、加载态、Toast 基础齐全**：列表有 loading，Toast 有 `role="alert"` 与 `aria-live="polite"`，并考虑安全区。

这些部分不建议推翻，后续修复应沿用现有 token、间距和弹窗体系。

## 3. P0：发布前必须修复

### UX-001 编辑配置无未保存保护，关闭即丢弃

**现象与证据**

- 编辑弹窗直接使用 `CreamDialog`，只传入 `v-model/title/width/inline`，没有 `before-close` 或脏数据检查（`src/views/new/config-view/EditDialog.vue:2-7`）。
- `CreamDialog` 默认 `closeOnOverlay: true`，点击遮罩、Esc、右上角 × 都会直接关闭（`src/components/CreamDialog/index.vue:98-112, 168-171`）。
- 底部「取消」同样直接 `visible = false`（`EditDialog.vue:408-410`）。
- 重新打开时表单内部状态会被重置（`EditDialog.vue:485-500`），未保存内容不可恢复。

**实测**

在表单编辑中输入 `ui-review-dirty`，按 Esc：弹窗立即关闭，**没有出现任何确认提示**；重新打开后该值已恢复为空。整个过程无 Toast、无恢复入口。

**影响**

- 用户编辑大段 TOML、调整多个高级开关或模板后，一次误点遮罩或 Esc 就全部丢失。
- Web 配置编辑弹窗（`WebConfigForm.vue`）使用同一个 `CreamDialog`，存在同样问题。

**建议**

- 为编辑弹窗建立 `initialSnapshot` 与 `isDirty`，关闭前统一走 `beforeClose`。
- 有改动时弹出三选一：**保存 / 放弃修改 / 继续编辑**；点击遮罩不要直接关闭（`closeOnOverlay=false`）。
- Android 返回键、路由离开、窗口关闭也应走同一守卫。
- 若实现成本高，至少先加「放弃未保存的修改？」确认，并把「取消」改为显式「放弃修改」。

---

### UX-002 「清除缓存」实际清空全部 localStorage

**现象与证据**

- 设置页「清除缓存」调用 `useStorage('localStorage').clear()` 后直接刷新（`src/components/SettingsDialog/index.vue:1104-1115`）。
- `clear()` 仅排除 `dynamicRouter` / `serverDynamicRouter` 两个键（`src/hooks/web/useStorage.ts:34-43`），其余键全部删除。
- 锁屏密码属于 Pinia `easytier` store 的持久化字段（`src/store/modules/easytier.ts:67, 416, 475-479`），会随 `easytier` 键一起被删除。
- 主题 `theme`、语言 `lang`、引导 `settings.onboardingDone`、自动运行配置、最近选择等也都是 localStorage 键。

**影响**

- 用户以为只是清"缓存"，实际丢失锁屏密码、主题、引导状态、语言、自动运行偏好和最近选择。
- 无法撤销，且刷新后界面外观与行为会突然回到初始状态，容易让用户误以为应用损坏。

**建议**

- 将「清除缓存」改为白名单清理：只清日志缓存、镜像探测缓存、临时 UI 状态等非关键键。
- 单独提供「重置应用设置」，明确列出会清除的项目，使用二次确认甚至输入确认词。
- 锁屏密码不应被"缓存清理"隐式删除；如确需重置，应单独提供「移除锁定密码」并二次确认（当前清除按钮已有确认，保留即可）。
- 文案改为「清除临时数据」或「清理缓存（不会删除密码与主题）」，避免歧义。

### UX-003 非法 TOML 仍可保存，可能写坏配置文件

**现象与证据**

- 代码模式保存时先尝试 `toml.parse`，失败后被 `catch { /* 解析失败按原样保存 */ }` 吞掉，仍将原始内容交给父组件写盘（`EditDialog.vue:876-904`）。
- 表单模式解析失败时，`parseFormData()` 返回 `false` 只阻止"表单 → 代码"回写（`EditDialog.vue:801-813`），并**不阻止保存**。
- 保存成功后父组件直接覆盖原配置文件（`src/views/new/config-view/index.vue:778-795`），没有备份步骤。
- 页脚仅有「修改后点击保存将覆盖原配置文件」的低对比提示，没有语法错误提示。

**影响**

- 用户少写一个引号或括号，也能"保存成功"，下次启动才由内核报错，问题定位成本高。
- 若覆盖的是唯一配置文件，用户可能失去可用的旧版本。

**建议**

- 保存前统一执行 `toml.parse`，失败时在编辑器下方显示明确错误（行号/列号），禁用保存按钮。
- 表单模式必须检查 `formParsedOk`；解析失败时显示错误横幅并禁止保存。
- 覆盖写盘前生成带时间戳的 `.bak`，或使用原子写入 + 备份。
- 可复用现有 `compatIssues` 提示位，把语法错误与版本兼容错误分成两类展示。

## 4. P1：下个迭代应完成

### UX-101 配置详情读取失败时静默展示演示数据

- `loadConfigDetail` 在读取或解析失败时直接调用 `getDemoConfig(...)`（`src/views/new/config-view/index.vue:521-548`），演示数据中包含 `tokyo-relay-01`、`global-mesh`、`10.0.0.0/8` 等虚构内容（同文件 `675-738`）。
- 用户看不到任何"读取失败"标识，会把这些值当成真实配置；若据此排查网络或做删除决策，风险很高。
- **建议**：生产环境不要回退演示数据。改为独立错误态：「读取失败」+ 重试 + 打开配置目录 + 查看日志。浏览器 Mock 可保留演示，但必须显示醒目的「演示数据」徽标。

### UX-102 关键色对比度不足

按 `src/styles/theme.css:4-25, 137-150` 的 token 计算：

| 组合 | 对比度 | 用途 | WCAG AA（正文 4.5:1） |
| --- | --: | --- | --- |
| 白色 `#ffffff` / 成功绿 `#7fba8a` | **2.26:1** | 「运行 / 启动」主按钮 | 不通过 |
| 粉色 `#e8a0a0` / 白卡 `#ffffff` | **2.11:1** | 删除、错误、强调文字 | 不通过 |
| 奶油 muted `#c8bdb2` / 背景 `#fdf8f4` | **1.75:1** | 描述、PID、状态、标签 | 严重不通过 |
| 奶油 muted `#c8bdb2` / 白卡 `#ffffff` | **1.85:1** | 卡片内说明、标签 | 严重不通过 |
| 暗色 muted `#5a6b80` / 卡 `#1b2838` | **2.74:1** | 暗色描述、标签 | 不通过 |
| 主文字 `#4a3728` / 背景 `#fdf8f4` | 10.66:1 | 标题、正文 | 通过 |

- 这些颜色被大量用于 9–12px 小字，实际可读性比数值更差；运行按钮的文字在浅绿底上尤其吃力。
- **建议**：
  - 成功按钮底色改为 `#3f7f55`（白字约 4.80:1）或改用深色文字。
  - 错误/删除文字改用 `#b4544f`（白底约 4.86:1，奶油底约 4.61:1）。
  - muted 文字提升到 `#7a6a58`（白底 5.21:1，奶油底 4.94:1），暗色 muted 提升到 `#8a9bb0`（暗卡 5.26:1）。
  - 9–11px 的小字只用于非必要元数据，正文与状态至少 12px。
  - 用对比度工具复核所有派生色，避免只改主 token 后局部仍不达标。

### UX-103 伪按钮广泛存在，键盘与读屏不可达

实测主题列表：`.td-item` 为 `DIV`、`tabIndex=-1`、`role=null`、`aria-selected=null`，列表内可聚焦元素数量为 **0**。同类问题还出现在：

- 主题项：`src/components/ThemeDialog/index.vue:14-24`
- 编辑弹窗高级开关 / 安全模式开关：`EditDialog.vue:153-160, 274-303, 330-340`
- 模板下拉选项：`EditDialog.vue:49-56`
- 服务安装方式（NSSM / 官方 CLI）：`src/views/new/web-config-view/index.vue:197-213`
- 控制台地址：`src/views/new/web-config-view/index.vue:125`
- 设置页镜像源列表：`src/components/SettingsDialog/index.vue:349-364`
- 引导页圆点：`src/components/OnboardingGuide/index.vue:90-99`

**影响**：Tab 顺序直接跳过这些控件，Enter/Space 无效，读屏只读出普通文本。键盘用户无法更换主题、切换高级开关、选择安装方式或访问 Web 控制台。

**建议**：统一改成原生 `button` / `input[type=checkbox|radio]`；需要自定义外观时用 `<label>` 包裹真实 input。切换类控件加 `aria-pressed` 或 `aria-checked`，列表选择加 `role=radiogroup/radio` + `aria-checked`。保留现有视觉样式，只更换语义元素。

### UX-104 表单控件缺少标签与 Tab 语义

DOM 实测与代码证据：

- 设置开关：`input[type=checkbox]` 的 `aria-label=null`，其 `labels` 数组唯一一项的文本为 **空字符串**，即无可访问名称；同页 4 处开关均如此（`SettingsDialog/index.vue:92-99, 240-265`）。
- 刷新间隔：`.sd-number` 无 `id`、无 `aria-label`、`labels.length=0`（`SettingsDialog/index.vue:158-170`）。
- 设置分类：按钮无 `role=tab`、无 `aria-selected`（`SettingsDialog/index.vue:5-13`，实测均为 `null`）。
- 锁屏密码输入：无 `label`、无 `aria-label`，只靠 placeholder（实测；`SettingsDialog/index.vue:510-520`）。
- Web 配置表单的 `<label class="wcf-label">` 没有 `for`，input 没有 `id`（`WebConfigForm.vue:9-15` 等全部字段）。
- 锁屏页错误文案无 `aria-live`，密码输入无 label（`src/App.vue:189-196`）。
- 多个图标按钮只有 `title`，没有 `aria-label`（语言、主题、设置入口；`NewLayout.vue:50-120`）。

**建议**：为每个控件建立稳定的 `id` 与 `for`，或使用 `aria-labelledby`；分类导航补齐 `role=tablist/tab` 与 `aria-selected`；错误信息加 `role=alert`；图标按钮统一补 `aria-label`。

### UX-105 移动端设置页 inline 失效，且只能看到第一个分类

- `settings-view` 以 `<SettingsDialog v-model="visible" inline />` 承载二级页（`src/views/new/settings-view/index.vue:3`）。
- `SettingsDialog` 只声明了 `modelValue` prop（`src/components/SettingsDialog/index.vue:713`），模板却有**两个根节点**：主弹窗（第 2 行）与确认弹窗（第 644 行）。Vue 无法把 `inline` 透传到任何一个根节点，控制台出现 `Extraneous non-props attributes (inline)`。
- 结果：移动端设置页仍是带遮罩的弹窗，而非页面内卡片（截图 08、10 可见深层遮罩与浮层标题栏）。
- 即使 inline 修好，分类导航在 ≤640px 仍只显示「通用设置」：基础 `.sd-nav-item { width: 100% }`（`index.vue:1273`）未被窄屏规则覆盖，窄屏只加了 `flex-shrink: 0; white-space: nowrap`（`index.vue:2026-2042`），每个 tab 占满一行，其余分类被推到横向滚动区且滚动条被隐藏。

**建议**：

- 为 `SettingsDialog` 增加 `inline` prop，并传给主 `CreamDialog`；确认弹窗保持独立遮罩。
- 或将两个根节点包进一个容器/把确认弹窗移至 `Teleport` 内，确保属性可透传。
- 窄屏覆盖 `.sd-nav-item { width: auto; }`，为横向导航加渐隐边缘或可见滚动条；也可改为两行换行布局。

### UX-106 全局隐藏滚动条 + FAB 无内容避让

- 布局壳强制隐藏所有页面滚动条：`.nl-content` 自身 `scrollbar-width: none`（`NewLayout.vue:893-900`），并在全局样式块中再次对所有子元素执行 `::-webkit-scrollbar { display:none !important }`、`* { scrollbar-width:none !important }`（`NewLayout.vue:980-989`）。
- `.nl-content` 只有 24px（窄屏 16px）内边距，没有为 FAB 预留底部空间（`NewLayout.vue:852-857, 888-890`）。
- FAB 固定 `right:24px; bottom:24px`，尺寸 40px（触屏 48px）（`src/components/FloatingMenu/index.vue:93-112, 212-220`）。

长页面因此既没有"还能继续滚"的视觉线索，底部内容又可能被 FAB 压住。截图 03/06/07/12 中均可看到内容被视口或 FAB 截断；配置页右下角还有一个独立的悬浮「刷新配置」胶囊，与 FAB 共同挤占同一区域。

**建议**：

- 恢复 `nl-content` 和长详情面板的细滚动条，或在滚动容器边缘添加渐隐提示。
- 为 `.nl-content` 增加至少 `padding-bottom: 88px` 的 FAB 避让；更优做法是在列表/详情页把 FAB 移入工具栏或详情操作区。
- 配置页的「刷新配置」与 FAB 刷新功能去重，只保留一个入口。

### UX-107 锁屏密码：失焦即生效、无确认、无反馈

- 密码输入绑定 `@keyup.enter` 与 `@blur` 提交（`SettingsDialog/index.vue:518-519`）。
- 提交逻辑没有最短长度、没有二次确认，也没有成功 Toast；输入任意字符后点到别处就会静默设置密码（`index.vue:788-799`）。
- 没有 `label`，只靠 placeholder；锁屏错误无 `aria-live`（`App.vue:189-196`）。
- 用户可能误设一个自己都不知道的密码，之后切窗即被锁屏。

**建议**：改为显式「设置密码」按钮 + 确认密码输入；失焦不提交；至少 4–6 位并给出强度/错误提示；设置成功 Toast；锁屏密码错误使用 `aria-live` 并增加尝试节流。

### UX-108 监控空态与失败态具有误导性

- 左侧列表只显示运行中的配置：`displayList` 先过滤 `runningSet`（`src/views/new/monitor/index.vue:413-422`）。
- 空态却复用 `t('newCommon.noConfig')`（同文件 `28-34`）。当用户有 5 个配置但全部停止时，界面显示「暂无配置」，与事实不符。
- 轮询连续失败 3 次后直接 `stopPolling()` 并清空 `selectedData`（同文件 `907-918`），没有错误提示、没有重试按钮、没有"数据已停止更新"标识；右侧详情直接消失（模板 `38` 行 `v-if="selectedData"`）。
- 用户只能离开页面再进入（或切后台再回来）才能恢复，且不知道发生了什么。

**建议**：

- 区分「还没有配置」「有配置但均未运行」「已运行但监控数据获取失败」三种空态。
- 失败时保留最后一次数据并标记"已过期"，显示重试按钮；或指数退避重试，而不是静默停止。
- 空态提供「去配置」/「启动配置」入口。

### UX-109 默认 1000×650 下配置详情头部被挤压

- Tauri 默认窗口为 1000×650（`src-tauri/tauri.conf.json5:29-41`）。
- 配置页详情头部的换行规则只写在 `@media (width <= 900px)` 内（`src/views/new/config-view/index.vue:1310-1338`），1000px 落在断点之上，头部仍是单行 flex 布局。
- 截图 12 中：标题「东京中继节点」被拆成两行，状态徽标「已停止」拆成两行，四个操作按钮被挤到多行且文字几乎不可读；「关闭」按钮的浅色文字在奶油底上近乎消失。

**建议**：

- 把详情头部换行断点提升到 1100px，或对头部单独使用 `flex-wrap: wrap` + `min-width`，不依赖页面级断点。
- 将四个操作改为 2×2 小网格，或只保留一个主操作，其余放入「更多」菜单。
- 为窗口声明 `minWidth/minHeight`（如 900×600），避免继续压缩。

### UX-110 操作层级反转，术语不统一

- 运行中卡片：禁用的「启动 / 运行」仍是绿色实心按钮，只是 `opacity:0.3`；真正可点的「停止 / 关闭」是极浅的粉色文字（截图 01、02、17）。
- 停止中的详情：可点的「运行」是绿色实心，禁用的「关闭」是浅粉文字——两种状态的主次表达几乎一样，用户需要先读状态再判断哪个能点。
- 术语在同一产品内混用：总览用「启动/停止」，配置页用「运行/关闭」，Web 配置列表用「未运行」而详情徽标用「已停止」，窗口关闭也叫「关闭」。
- 列表卡片与详情面板重复提供同一组启动/停止按钮，容易误触。

**建议**：

- 生命周期统一为「运行 / 停止」，窗口操作用「关闭窗口」；状态统一为「运行中 / 已停止」。
- 禁用状态不要保持主按钮实心视觉：可替换为状态标签（运行中），或使用中性描边 + 明确禁用。
- 每个上下文只保留一个主操作；列表卡片保留快捷操作时，详情头部不再重复同一按钮。

## 8. 平台专项

### 8.1 桌面

- 默认 1000×650 是问题最集中的窗口尺寸：配置详情头部与操作区需要专门的中等宽度断点。
- 自定义标题栏只有关闭，没有最小化/最大化；对习惯 Windows 标准窗口的用户是明显缺失。
- 隐藏滚动条在桌面鼠标滚轮场景下尤其不利，用户很难判断长详情还能滚动多少。
- Web 配置、编辑弹窗在 1122 宽度下视觉良好，但关闭守卫与无障碍语义缺失。

### 8.2 Android

- 设计策略正确：桌面专属的托盘、服务管理、核心路径、镜像源与下载安装均隐藏；配置编辑/设置/主题改用二级页路由。
- 但设置二级页当前退化为遮罩弹窗，且分类不可见（UX-105），这是 Android 端最直接的可用性缺陷。
- `config-view` 单实例切换仍使用原生 `window.confirm`（`config-view/index.vue:615-621`），与全站 `CreamDialog` 不一致，也无法主题化/统一无障碍行为。
- 移动端主从布局（列表 ↔ 详情）思路正确，但统计卡、详情头部和 FAB 安全区还需逐页打磨。
- 本次未在真机验证 VPN 状态、通知、锁屏返回键和文件选择器。

### 8.3 浏览器 Mock

- Mock 是项目明确要求的能力（AGENTS.md），但 `App` 初始化在浏览器中因托盘调用中断，破坏了「无 Tauri 环境可完整预览」的约定。
- Mock 下的演示配置/节点数据可保留，但必须在 UI 上显式标注「演示数据」，避免与真实读取失败混淆。
- 建议为托盘、窗口、锁屏等桌面 API 增加统一 mock，而不是在每个页面自行降级。

## 10. 验收清单

### 数据与保存

- [ ] 编辑配置有未保存守卫；Esc、遮罩、取消、Android 返回、窗口关闭均会提示。
- [ ] 代码模式语法错误会阻止保存并定位到行列；表单解析失败会阻止保存。
- [ ] 保存覆盖前生成 `.bak` 或原子备份。
- [ ] 「清除缓存」只清临时数据；锁屏密码、主题、语言、引导状态不受影响。
- [ ] 配置详情读取失败显示错误态与重试，不展示演示数据（或明确标注「演示」）。

### 可访问性

- [ ] 主题项、开关、安装方式、控制台链接、引导圆点均可用 Tab 聚焦、Enter/Space 操作。
- [ ] 所有输入、开关、数字框、密码框都有可访问名称。
- [ ] 设置分类具备 `tablist/tab` 与 `aria-selected`。
- [ ] 自定义控件有 `:focus-visible` 焦点环，焦点环在各主题下清晰可见。
- [ ] 关键文字/按钮对比度达到 WCAG AA；成功按钮白字 ≥4.5:1，muted 正文 ≥4.5:1。
- [ ] 锁屏错误、保存错误、监控失败均通过 `aria-live`/`role=alert` 播报。

### 布局与响应式

- [ ] 1000×650 下配置详情标题、徽标、四个操作不换行错位、不遮挡。
- [ ] 390×844 下设置页以页面内卡片展示，所有分类可见或有明确滚动提示。
- [ ] 390×844 下统计卡数值/单位不折行，编辑表单不横向溢出。
- [ ] 长内容有可见滚动线索；FAB 不遮挡任何操作或最后一屏内容。
- [ ] 窗口声明最小尺寸，标题栏提供最小化/最大化/关闭。

### 交互与状态

- [ ] 运行中的「运行」不再以实心主按钮呈现；停止操作清晰可辨。
- [ ] 全局统一使用「运行/停止」；「关闭」只用于窗口。
- [ ] 监控连续失败有提示、重试或退避；空态区分无配置与无运行实例。
- [ ] 锁屏密码需二次确认，设置成功有反馈，失焦不提交。
- [ ] 引导流程可键盘完成，覆盖层具备 dialog 语义与焦点圈定。
- [ ] 浏览器 Mock 下 `pnpm dev` 无未捕获错误，锁屏/托盘/WEB 配置预览可用。
